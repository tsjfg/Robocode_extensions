# Robocode_extensions

> 关于 Robocode 一些好用的拓展 —— 面向 `E6` / `E7` / `M6` 设备的积木扩展包集合。

本仓库收集并维护可用于 Robocode 编程平台的第三方（非官方）拓展。每个拓展以独立目录存放，通过 `config.json` 声明元信息、`index.js` 定义积木逻辑，配合图标与资源文件即可被平台加载。

## 🔌 拓展列表

| 拓展 | 目录 | 说明 |
| --- | --- | --- |
| **数据测试** | `robocode拓展/test/` | 调试用拓展：支持 8 路舵机转动与速度控制，可将舵机角度、马达编码值实时显示在屏幕上；并提供 8 格触摸任务面板 |
| **舵机狗** | `robocode拓展/舵机狗2/` | 四足舵机狗控制拓展：前进 / 后退 / 转向 / 站立 / 坐下 / 趴下 / 狗叫 / 抬腿 / 自定义姿势等 |
| **PID巡线** | `robocode拓展/PID巡线/` | 巡线底层拓展：4 光电差值法 / 循迹卡重心法双模式 PID，参数按电机类型（E005）自动适配，支持巡线距离、路口停车、冲出路口、转到线等 |

三个拓展均生成 **Python** 代码，支持设备：`E6`、`E7`、`M6`。

| `前进 [steps] 次` | 按步态序列前进 |
| `后退 [steps] 次` | 按反向步态序列后退 |
| `左转 [steps] 次` | 原地左转（每次内部循环 6 拍） |
| `右转 [steps] 次` | 原地右转（每次内部循环 6 拍） |
| `站立` | 四条腿复位站立 |
| `坐下` | 呈现坐姿（后腿抬升） |
| `趴下` | 四腿全部压低 |
| `狗叫 [叫声类型]` | 播放叫声音频（叫声1 / 叫声2） |

| `将姿势设为左手[LF] 右手[RF] 左脚[LB] 右脚[RB]` | 直接指定四腿角度自定义姿势 |
| `释放所有舵机` | 将 1～4 号舵机全部释放 |

| `将速度设为[speed]，节拍设为[time]秒` | 修改全局速度与步态节拍参数 |

## 🛤 PID巡线（`PID巡线/`）

面向巡线小车的底层拓展，内置 **PID** 循迹算法，自动兼容 **4 光电** 与 **循迹卡（7 路）** 两种传感器，并按 **电机类型（E005）** 自动选用对应参数：

- **4 光电 —— 差值法**：误差 = `sensor.GetLightSensor(3) - sensor.GetLightSensor(2)`，直接用原始模拟光值，不做归一化；
- **循迹卡 —— 重心法**：7 路黑度加权求连续偏差，误差归一化到 ±100。

所有底层函数在首次使用任一积木时自动注入到生成的 Python 代码中（`functionNames_` 字典去重）。

### 电机类型自适应

底层常量与 PID 参数按 **E005（`1` = 白红电机，`2` = 灰红电机）** 各存一列，运行时由 `apply_motor_param()` 每个巡线周期自动装载对应的一列，因此中途更换电机型号或修改参数都能立刻生效。（实测：循迹卡 + 白红电机 `Kp=0.8` 刚好，换成灰红电机便明显摇摆，故灰红默认把 `Kp` 减半。）

### 传感器与算法

| 模式 | 传感器 | 巡线算法 | 压线判定 |
| --- | --- | --- | --- |
| 4 光电（`E007 = 4`） | P1 / P2 / P3 / P4 | 差值法 `误差 = 光值(P3) − 光值(P2)`（线在左为正、在右为负） | `sensor.GetLightSensorData(i) == 巡线颜色` |
| 循迹卡（`E007 = 7`） | 挂在 P1 端口，通道 1～7 | 重心法 权重 `[-3,-2,-1,0,+1,+2,+3]`，误差归一化 ±100 | `trace.GetTraceV2I2CState(P1端口, i) == 巡线颜色` |

> 传感器安装：车头朝前，从车的左侧到右侧依次编号。模式由 `E007` 自动判断，也可用底层常量 `PID_FORCE_MODE` 强制指定（`4` = 4 光电 / `7` = 循迹卡）。

### 积木清单

| 积木 | 说明 |
| --- | --- |
| `初始化 巡线颜色 [黑线/白线]` | 设置巡线颜色（黑线 = 1，白线 = 0）并注入底层 |
| `设置PID 电机 [白红/灰红] Kp [kp] Ki [ki] Kd [kd] 基础速度 [base]` | 修改**循迹卡重心法**的参数，按所选电机写入对应参数列。默认白红 `Kp=0.8`、`Ki=0`、`Kd=1.6`、基础速度 `50`；灰红 `Kp=0.4` |
| `设置4光电PID 电机 [白红/灰红] Kp [kp] Ki [ki] Kd [kd]` | 修改**4 光电差值法**的参数（使用原始光值差，量纲与循迹卡那组完全不同）。默认白红 `Kp=0.015`、`Kd=0.03`；灰红 `Kp=0.010`、`Kd=0.03` |
| `巡线遇路口停 速度 [speed] 路口类型 [jtype] 调整编码值 [adjust]` | 沿黑线巡线，遇到指定路口后停车。路口类型：左 / 右 / T / 左+冲出 / 右+冲出 / T+冲出；`adjust` 为过路口后继续行走或倒退的编码值（带冲出时冲出距离 = `E006 + adjust`） |
| `巡线距离 速度 [speed] 编码值 [bmp]` | 沿黑线巡线前进 `bmp` 个编码值 |
| `[左/右] 转到线` | 原地转向（左轮后退 / 右轮前进）直到重新压线，按「先到 → 后到」两段通道判定 |
| `走距离 速度 [sp] 编码值 [bmp]` | 不巡线，用编码器差分同步笔直前进 / 倒退 `bmp` 个编码值（正前进、负倒退） |
| `转编码值 左轮速度 [spl] 右轮速度 [spr] 编码值 [bmp]` | 左右轮以不同速度旋转，任一轮走满 `bmp` 个编码值即停 |

### 关键可调参数（生成的代码顶部）

参数表均按 `[白红, 灰红]` 两列存放，由 E005 自动选用：

| 参数 | 默认值（白红 / 灰红） | 说明 |
| --- | --- | --- |
| `PID_KP_TAB` / `PID_KI_TAB` / `PID_KD_TAB` | `[0.80, 0.40]` / `[0, 0]` / `[1.60, 1.60]` | 循迹卡重心法的比例 / 积分 / 微分系数 |
| `PID_KP4_TAB` / `PID_KI4_TAB` / `PID_KD4_TAB` | `[0.015, 0.010]` / `[0, 0]` / `[0.030, 0.030]` | 4 光电差值法的系数（输入为原始光值差，量纲不同） |
| `PID_BASE_TAB` | `[50, 50]` | 基础速度，必须大于电机死区 |
| `PID_MAX_OUT` | `60` | 差速限幅（±） |
| `PID_MIN_SUM` | `30` | 黑度总和下限，低于此值判为脱线（循迹卡重心法） |
| `PID_I4_LIMIT` | `20000` | 4 光电差值法的积分限幅（光值单位），防止积分饱和 |
| `PID_MOTOR_ADDR` | `5` | E005：电机类型地址（`1` = 白红 / `2` = 灰红） |
| `PID_TRACE_PORT` | `1` | 循迹卡插在哪个端口（P1～P8） |
| `PID_FORCE_MODE` | `0` | `0` = 按 E007 自动判断；`4` = 强制 4 光电；`7` = 强制循迹卡 |
| `PID_DEADZONE` | `0` | 电机死区（速度单位 0～100），实测后填 |

## 🚀 安装与使用

1. 将 `robocode拓展/` 目录整体放入 Robocode 平台的拓展加载目录中；
2. 在平台的项目中刷新 / 重新加载拓展列表；
3. 即可在积木面板中找到 **数据测试**、**舵机狗** 与 **PID巡线** 三组积木，拖拽并生成 Python 代码后上传至 `E6` / `E7` / `M6` 设备运行。

> 具体加载路径与刷新方式请参考你所使用的 Robocode 平台文档。

## 🛠 开发指南

每个拓展目录的标准结构如下：

```
扩展名/
├── config.json        # 拓展元信息
├── index.js           # 积木逻辑（window.Scratch 扩展）
├── <cover>.png        # 封面图（可选）
├── img/
│   ├── blockIcon/     # 积木图标 SVG
│   └── menuIcon/      # 菜单图标 SVG
└── ...                # 其他资源（音频、图片等）
```

### config.json 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 拓展唯一 ID，需与 `index.js` 中的类 ID 对应 |
| `name` | string | 拓展显示名称 |
| `description` | string | 拓展描述 |
| `icon` | string | 图标路径（可留空） |
| `cover` | string | 封面图片文件名 |
| `codeTypes` | string[] | 生成的代码类型，如 `["Python"]` |
| `order` | string | 排序权重 |
| `supportDevice` | string[] | 支持的设备型号 |
| `official` | bool | 是否为官方拓展（本仓库均为 `false`） |

### index.js 要点

- 必须从 `window.Scratch` 解构出所需 API（如 `ArgumentType`、`BlockType`、`ScratchBlocks` 等）；
- 导出一个以拓展 ID 命名的 `xxxBlock` 类；
- `_generateCode()` 定义各积木生成的 Python 代码，并可用 `ScratchBlocks.Python.Import(...)` 声明所需模块；
- `getInfo()` 返回积木面板的定义（`blocks`、`menus`、颜色、图标、支持设备等）。

### 图标规范

- `img/blockIcon/` 与 `img/menuIcon/` 下存放 **SVG** 格式图标，需与 `index.js` 中 `this.imgs.blockIcon[...]` / `this.imgs.menuIcon[...]` 引用的文件名对应。
