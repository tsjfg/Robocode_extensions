# PID巡线 扩展

中鸣机器人（M6 / E6 / E7）的循线积木扩展。把 4 光电和循迹卡的 PID 巡线、
路口识别、定距行驶都封装成积木，参数按「电机类型 × 阵列类型」自动选组。

- 扩展 ID：`PIDXunXian0001E6E7M6`
- 支持设备：`E6` `E7` `M6`
- 生成语言：Python

## 二、7 个积木

### 1. 初始化 巡线颜色 `[黑线 / 白线]`

设定线是黑的还是白的。**放在程序最前面**，只影响后面拖的积木。

```python
set_line_color(1)      # 1 = 黑线，0 = 白线
```

它不是直接给变量赋值，而是调用函数改一个 list 元素。
这样即使平台把主程序包进函数里（局部作用域），底层也能读到正确的值。

### 2. 设置PID Kp `[]` Ki `[]` Kd `[]`（可选）

手动覆盖四组默认参数。**不用这个积木就走默认表**，用了就全部按这里填的算。

```python
set_pid_override(0.8, 0, 1.6)
```

注意：4 光电和循迹卡的误差量纲差两个数量级（0.015 vs 0.8），
这里填一组值会同时作用于两种阵列，**混用时不要用这个积木**。

### 3. 巡线遇路口停 速度 `[]` 路口类型 `[]` 调整编码值 `[]`

沿线走，遇到指定路口停车并响一声。

| 路口类型 | 判定条件 |
| --- | --- |
| 左路口 | 最左侧压线、最右侧不压线 |
| 右路口 | 最右侧压线、最左侧不压线 |
| T路口 | 两侧同时压线 |
| 左/右/T + 冲出 | 同上，但不停车，改为笔直冲过 `E006 + 调整编码值` |

`调整编码值` 可正可负：正数过路口后继续前进，负数笔直倒退。
不带冲出时，它就是「过路口后再走多少编码值」，填 0 即立刻停。

> 速度**只填正数**。倒退巡线的修正方向是反的，速度 ≤ 0 时直接返回。
> 路口类型不在 `1~6` 范围内时也直接返回，不会卡在「永远等不到路口」的死循环里。

```python
xunxian_stop_junction(50, 1, 0)      # 左路口，立刻停
xunxian_stop_junction(50, 6, 0)      # T路口 + 冲出，距离取 E006
xunxian_stop_junction(50, 2, 150)    # 右路口后再前进 150
xunxian_stop_junction(50, 1, -80)    # 左路口后倒退 80
```

### 4. 巡线距离 速度 `[]` 编码值 `[]`

沿线走固定距离后停，距离由两轮编码决定。

```python
xunxian_distance(50, 1500)
```

> 速度**只填正数**。倒退巡线时左右轮的修正方向是反的，PID 会越修越偏，
> 所以速度 ≤ 0 时函数直接返回，不做任何动作。

### 5. `[左 / 右]` 转到线

原地转，直到扫到线。速度固定 40，不用填。

```python
turn_left_line()       # 左轮后退 + 右轮前进
turn_right_line()
```

扫线通道：

| 阵列 | 左转 | 右转 |
| --- | --- | --- |
| 4 光电 | P1 → P3 | P4 → P2 |
| 循迹卡 | ch1 → ch4 | ch7 → ch4 |

### 6. 走距离 速度 `[]` 编码值 `[]`

不巡线，笔直走。速度带符号：正数前进，负数后退；编码值只填正数。

```python
go_straight(50, 1000)      # 前进 1000
go_straight(-50, 800)      # 倒退 800
```

带**停滞保护**：编码值连续 `PID_GO_TIMEOUT` 秒（默认 3 秒）没有增长，
就判定车走不动了（电机堵转 / 轮子被卡 / 编码器线没插上），
立刻停车并让主程序继续执行下一条积木，不会把整场比赛卡在这里。

只要车还在动，哪怕走得很慢也不会被这个保护打断——它看的是「有没有进展」，
不是「总共花了多久」。需要知道上一次是不是被强制结束时，可以调 `go_stalled()`。

### 7. 转编码值 左轮速度 `[]` 右轮速度 `[]` 编码值 `[]`

两轮以不同速度转，任意一轮走满编码值就停。用来原地转固定角度。

```python
turn_bmz(50, -50, 500)
```

## 三、数据地址

在控制器的「数据修改」页填这几个地址，程序运行时自动读取：

| 地址 | 含义 | 取值 |
| --- | --- | --- |
| `E005` | 马达类型 | `1` = 白红电机，`2` = 灰红电机 |
| `E006` | 冲出编码值 | 「+冲出」路口类型使用 |
| `E007` | 巡线阵列 | `4` = 4 光电，`7` = 循迹卡 |

`E005 × E007` 决定用哪一组 PID 参数，换电机不用改程序。

## 四、底层模块

生成的 Python 代码分成下面几块，按出现顺序排列。

### 配置区

| 模块 | 作用 |
| --- | --- |
| 地址定义 | `PID_MOTOR_ADDR` / `PID_MODE_ADDR` / `PID_OUT_ADDR` |
| `PID_KP_TAB` / `PID_KI_TAB` / `PID_KD_TAB` | 四组参数表，下标 = 电机序号 × 2 + 阵列序号 |
| `PID_SET_CFG` + `set_pid_override()` | 手动覆盖参数（积木 2 写入） |
| `PID_CFG` + `line_color()` / `set_line_color()` | 巡线颜色（积木 1 写入） |
| `motor_idx()` / `mode_idx()` / `param_idx()` | 读 E005 / E007，算出参数表下标 |
| `apply_param()` | 每个巡线周期装载一次当前生效的 Kp / Ki / Kd |

参数表默认值：

| 下标 | 组合 | Kp | Ki | Kd |
| --- | --- | --- | --- | --- |
| 0 | 白红 + 4 光电 | 0.015 | 0 | 0.030 |
| 1 | 白红 + 循迹卡 | 0.80 | 0 | 1.60 |
| 2 | 灰红 + 4 光电 | 0.010 | 0 | 0.030 |
| 3 | 灰红 + 循迹卡 | 0.40 | 0 | 1.60 |

> 灰红那两组是推测值（Kp 减半、Kd 保持），需要实测确认。

### 传感器区

| 模块 | 作用 |
| --- | --- |
| `use_trace()` | 当前是不是循迹卡（E007 = 7） |
| `count_one(n)` | 数一遍阵列里读到 1 的路数 |
| `trace_level()` | 判断「通道读到几才算压线」，黑白线统一走少数派判定 |
| `refresh_level()` | 每个巡线周期只判一次电平，避免反复读 I2C |
| `on_line(i)` | 第 i 路是否压线 |
| `read_black(i)` | 第 i 路的黑度（100 / 0），供重心法使用 |

压线电平为什么要自动判：不同批次循迹卡的固件约定不一样
（`1 = 检测到线` / `1 = 看到亮` / `1 = 看到黑`），写死任何一个都会让某种线巡反。
判据是「线是窄的，压线的通道永远是少数派」。

`trace_level()` 的返回值分三种情况：

| 返回值 | 含义 | 处理 |
| --- | --- | --- |
| `0` / `1` | 判定成功，这就是压线电平 | 缓存，之后直接用 |
| `-1` | 4:3 平局，或 7 路全 1（路口） | 不缓存；本周期按颜色约定兜底 |
| `-2` | 7 路全 0，一路都没读到 1 | 不缓存；本周期按「全不压线」处理 |

`-2` 必须和 `-1` 分开：全 0 说明车不在线上，要让 `on_line()` 全部返回 `False`
才能触发脱线找线。如果一律按颜色兜底，白线（`line_color() = 0`）+ `1 = 检测到线`
的卡会把 7 路全判成压线，`sum_v = 700`，车以为整排都压着线，直着冲出去不找线。

### 执行区

| 模块 | 作用 |
| --- | --- |
| `dead_zone(sp)` | 限幅 → 死区补偿 → 再限幅。`PID_DEADZONE = 0` 时只做限幅 |
| `speed_control(spl, spr)` | 限幅到 ±100 后写两个电机 |
| `wheel_dist()` | 两轮编码绝对值的平均，三个「走距离」类积木都用它 |
| `go_stalled()` | 上一次「走距离」是否因为停滞保护提前退出（`PID_GO_TIMEOUT`） |

`wheel_dist()` 不用单轮、也不用带符号平均的原因：
巡线走曲线时外侧轮多走，只看单轮会偏；单轮卡死时只看它会死循环；
带符号平均在满舵修正（内侧轮短暂反转）时会抵消，原地打转时恒为 0。

### 巡线区

| 模块 | 作用 |
| --- | --- |
| `chai_zhi_reset()` | 清空 4 光电的积分和微分历史 |
| `chai_zhi_xun_xian_once(speed)` | 4 光电差值法：误差 = 光值(P3) − 光值(P2) |
| `pid_reset()` | 清空循迹卡的状态（内部也会调 `chai_zhi_reset`） |
| `xunxian_once(speed)` | 巡线一个周期。按 E007 自动分发到差值法或重心法 |

两种算法：

- **4 光电 · 差值法**：直接比较 P2、P3 两路模拟光值的差，量纲几百~几千，Kp 很小。
  白线时误差符号整体反相，靠 `line_color()` 把左右轮对调。
- **循迹卡 · 重心法**：权重 `[-3,-2,-1,0,1,2,3]`，误差归一化到 ±100。
  脱线时沿最后一次的方向满舵找线，重新入线时跳过这一次 D 项。

### 路口区

| 模块 | 作用 |
| --- | --- |
| `junction_detect(jtype)` | 看最外侧连续 `PID_JUNC_EDGE` 路是否压线，判定左 / 右 / T |

### 运动封装区

| 模块 | 作用 |
| --- | --- |
| `run_straight_bmz(speed, bmp)` | 纯直行，`bmp` 正负决定前进 / 倒退 |
| `xunxian_stop_junction(...)` | 巡线到路口 → 可选冲出 → 停车 + 蜂鸣 |
| `xunxian_distance(speed, bmp)` | 巡线走固定距离 |
| `turn_ch(k)` | 按阵列类型取「转到线」的扫线通道 |
| `wait_on_line(ch)` | 原地转到第 ch 路压线，带保险丝 |
| `turn_left_line()` / `turn_right_line()` | 左 / 右转到线 |
| `go_straight(sp, bmp)` | 编码器差分同步的直线行驶 |
| `turn_bmz(spl, spr, bmp)` | 两轮差速转固定编码值 |

## 五、可调常量

生成代码顶部集中放着这些参数，改完重新下载即可：

| 常量 | 默认 | 说明 |
| --- | --- | --- |
| `PID_DEADZONE` | `0` | 电机死区（速度单位）。电机低速不转时按实测填，一般 5~15 |
| `PID_MAX_OUT` | `60` | 差速限幅（±）。调小转弯更柔和，调大修正更猛 |
| `PID_MIN_SUM` | `30` | 黑度总和低于此值判为脱线 |
| `PID_JUNC_EDGE` | `1` | 最外侧连续几路压线才算路口。改 2 可减少误判 |
| `PID_TRACE_PORT` | `1` | 循迹卡插在哪个端口 |
| `PID_TRACE_LEVEL` | `-1` | 压线电平。`-1` 自动，`0` / `1` 手动强制 |
| `PID_FORCE_MODE` | `0` | 强制阵列类型。`0` 按 E007，`4` / `7` 强制指定（调试用） |
| `PID_EXIT_MAX` | `300` | 「开过路口」内循环的保险丝（次） |
| `PID_TURN_MAX` | `10000` | 「转到线」等线的保险丝（次） |
| `PID_GO_TIMEOUT` | `3.0` | 「走距离」停滞保护（秒）。编码值连续这么久没增长就判定卡死并退出；`0` 关闭 |

> `PID_MAX_OUT` 比巡线速度大时（默认 60 > 50），满舵修正会让内侧轮短暂反转。
> 这是「原地找线」的能力，正常巡线碰不到；觉得脱线时转太猛就调到 40。

改 PID 参数优先改 `PID_KP_TAB / PID_KI_TAB / PID_KD_TAB` 三行，
不要去动 `apply_param()`。

## 七、常见问题

**白线巡不了**
先确认生成代码里有 `set_line_color(0)`，而不是 `var_xun_xian_yan_se = 0`。
两者不一样：前者才写得进底层读的那份数据。

**黑白线都往线外跑**
把 `PID_TRACE_LEVEL` 从 `-1` 改成 `1` 或 `0` 试一次。
判断方法：车摆正、ch4 压线，读 `trace.GetTraceV2I2CState(1, 4)`，
读到几就填几。这个常量只管循迹卡，不影响 4 光电。

**电机低速嗡嗡响但不转**
填 `PID_DEADZONE`。单位是速度值不是毫秒，从 5 开始往上试。

**灰红电机摇摆明显**
默认已把 Kp 减半（0.40）。还摇就继续降到 0.30，或把 Kd 提到 1.8。

**过了一个路口后开始跑偏**
检查是不是旧版本。旧版会把路口的「全压线」误判成压线电平 0，
过完路口整片判断就反了；当前版本已修（`cnt == 7` 不缓存）。

**走距离总是差一点**
`wheel_dist()` 取的是两轮平均，和只看左轮相比，同样的编码值会走得稍远。
按实测微调编码值即可。

**走距离走了一半就停**
大概率是停滞保护触发了：编码值连续 `PID_GO_TIMEOUT` 秒（默认 3 秒）没有增长。
先查电机是不是堵转、轮子是不是被线绊住、编码器线有没有松。
如果确认是正常摩擦导致的短暂停滞，把 `PID_GO_TIMEOUT` 调大到 5 或 8 秒；
想彻底回到原来「一直等下去」的行为就填 0。
想在程序里区分「走完了」和「被踢出来了」，用 `go_stalled()` 读一下就知道。

**巡线距离填了负数，车不动**
这是故意的。倒退巡线时左右轮的修正方向会反过来，PID 越修越偏，
所以巡线类积木（巡线距离、巡线遇路口停）只接受正速度，≤ 0 直接返回。
真要倒退走一段，用「走距离」填负速度。

**转编码值转不动**
检查速度是不是落进了电机死区。现在 `turn_bmz` 也会过 `dead_zone()`，
死区填了 10、速度填 5 时会被抬到 14 而不是卡死；但如果 `PID_DEADZONE`
填得比速度还大，转弯会明显变慢，按实际电机调小即可。

**选了「左路口」，但地图上没有左路口，车一直跑**
这是设计行为：`巡线遇路口停` 会一直巡到遇见指定路口为止，没有超时。
如果车脱线后原地打转，说明线已经丢了，检查传感器或先加一个
`巡线距离` 兜底。

**4 光电白线时，巡线正常但「转到线」或路口判断不对**
4 光电的 `GetLightSensorData()` 极性由传感器固件决定，和 `PID_TRACE_LEVEL`
无关。巡线本身用的是模拟量差值，不受影响；只有路口判断 / 转到线依赖数字量。
遇到这种情况告诉我，需要给 4 光电单独加一套电平判定。
