> Robocode 拓展 · 巡线底层积木包 —— **4 光电差值法** 与 **循迹卡重心法** 双模式加权 PID，按电机类型和阵列类型自动切换参数组，自带路口识别、转向与编码值走位。

| 支持设备 | `E6` / `E7` / `M6` |
| 生成代码 | Python |
| 所需模块 | `rcu`、`math`、`motor`、`sensor`、`trace` |
| 积木颜色 | `#c0392b` / `#96281b` |

## 一、核心设计：一份底层，两级自适应

这个拓展的代码组织方式和普通积木包不太一样，理解这一点后面就都好办了：

**只要用到任意一个积木，整段约 480 行的巡线底层（常量 `CORE`）就会被整体注入到生成程序的定义区。** 所有积木都往同一个 `functionNames_` 键 `"PID巡线_底层"` 里写这份常量，字典去重，因此不管用了几个积木，底层都只有一份。

积木本身只生成一行调用，例如 `巡线距离 速度 50 编码值 1500` → `xunxian_distance(50, 1500)`。

在底层之上是**两级自适应**：

```
             E005（电机类型）      E007（阵列类型）
                   ↓                     ↓
             白红 / 灰红            4 光电 / 循迹卡
                   └──────────┬──────────┘
                              ↓
                  param_idx() = 电机序号 × 2 + 阵列序号
                              ↓
                    四组 Kp / Ki / Kd 参数表 [0..3]
```

`apply_param()` 会**每个控制周期都重新装载一次**，所以中途换电机、换阵列都能立刻生效，不用改代码。

## 二、传感器安装

**车头朝前，从车的左侧到右侧依次编号。**

### 模式 A：4 光电（`E007 = 4`）

- 插在 `P1 P2 P3 P4`
- 巡线用**差值法**：`误差 = 光值(P3) − 光值(P2)`，直接用原始模拟量
- 压线判定用数字量：`sensor.GetLightSensorData(i) == var_xun_xian_yan_se`

> 只用了中间两路做 PID，最外侧 P1 / P4 **专门用来判路口**。

### 模式 B：循迹卡（`E007 = 7`）

- 插在 `P1` 端口，使用通道 `1 ~ 7`
- 巡线用**重心法**：权重 `[-3,-2,-1,0,+1,+2,+3]`，误差归一化到 ±100
- 读取：`trace.GetTraceV2I2CState(P1端口, i)`

## 三、PID 参数表

参数默认写死在底层，写在积木里的「设置PID」会覆盖它们。

| 下标 | 组合 | Kp | Ki | Kd |
| --- | --- | --- | --- | --- |
| `[0]` | 白红 + 4 光电 | 0.015 | 0.000 | 0.030 |
| `[1]` | 白红 + 循迹卡 | 0.80 | 0.00 | 1.60 |
| `[2]` | 灰红 + 4 光电 | 0.010 | 0.000 | 0.030 |
| `[3]` | 灰红 + 循迹卡 | 0.40 | 0.00 | 1.60 |

**为什么差了两个数量级？** 因为两种模式的误差量纲完全不同：

- 4 光电是原始模拟光值，量纲几百~几千 → Kp 在 `0.01` 级；
- 循迹卡已经归一化到 ±100 → Kp 在 `1` 级。

这就是为什么必须分表存储，一套参数不可能同时适配两种传感器。

**灰红电机为什么 Kp 减半？** 实测灰红电机用白红的参数会明显摇摆，Kp 减半、Kd 不变相当于提高阻尼比，正好压住摇摆。

### 手动覆盖

`设置PID Kp [kp] Ki [ki] Kd [kd]` 积木生成四行赋值：

```python
PID_KP_SET = 0.8
PID_KI_SET = 0
PID_KD_SET = 1.6
PID_USE_SET = 1
```

一旦 `PID_USE_SET = 1`，`apply_param()` 就直接用这组值，**四组参数表暂时失效**。想回到自动选参，把这个积木删掉即可。

> ⚠️ 因为 `PID_USE_SET` 是**全局唯一的一份**，这个积木用两个、且值不同时，最终生效的是程序中**最后出现**的那一组。想做"分段切换参数"，需要手动改生成的 Python。

## 五、逐积木详解

### 1. `初始化 巡线颜色`

必须放在程序最前面。除了设置 `var_xun_xian_yan_se`，它还负责 `Import` 五个模块并注入底层。

> 为什么用"积木体赋值"而不是 `definition_variables`？因为底层定义一定在程序最前面生成，而积木体在它之后 —— 这样赋值一定能覆盖底层的默认值，不会被反过来覆盖。

**颜色 = `1` 表示黑线、`0` 表示白线**，这个值会同时影响：压线判定、差值法的**正负号方向**、循迹卡的压线电平判定。

### 2. `巡线遇路口停`

六个路口类型：

| 下拉 | 值 | 含义 |
| --- | --- | --- |
| 左路口 | 1 | 最左侧压线、最右侧不压 |
| 右路口 | 2 | 最右侧压线、最左侧不压 |
| T路口 | 3 | 两侧同时压线 |
| 左路口+冲出 | 4 | 判到左路口后**不停车**，继续直行冲出 |
| 右路口+冲出 | 5 | 同上 |
| T路口+冲出 | 6 | 同上 |

`+冲出` 的三种在内部被换算回 1/2/3，同时置一个 `out_flag`：

```python
if jtype > 3:
    out_flag = 1
    jtype = jtype - 3
```

判到路口后的处理：

```python
while junction_detect(jtype):
    xunxian_once(speed)
    guard += 1
    if guard >= PID_EXIT_MAX:   # 保险丝，默认 300 次
        break

if out_flag == 1:
    run_straight_bmz(speed, rcu.GetData(PID_OUT_ADDR) + adjust)  # E006 + adjust
else:
    run_straight_bmz(speed, adjust)                              # 只走 adjust
```

几个设计细节：

- **先开过路口区域再停车**，否则同一个路口会被反复判到，小车在原地抽搐；
- **`guard` 是保险丝**：如果路口位型因为反光一直不消失，最多再跑 300 个周期就强行放行，避免死循环；
- **`adjust` 可正可负**：正走过路口后继续前进，负则倒退。不带`+冲出`时 `adjust = 0` 就是"见到路口立刻停"；
- 停车后会**响两声蜂鸣**（`SetInBeep` 10→0→10ms 的节奏）作为到达提示。

### 3. `巡线距离 / 走距离 / 转编码值`

三个都是**按编码值**走位，但行为不同：

| 积木 | 编码值符号 | 速度符号 | 停止条件 |
| --- | --- | --- | --- |
| `巡线距离` | 只取**绝对值** | 正数 | M1 走满 `\|bmp\|` |
| `走距离` | 只取**绝对值** | **可为负 = 倒退** | M1 走满 `\|bmp\|` |
| `转编码值` | 只取**绝对值** | 左右轮独立，可为负 | **任意一轮**走满 `\|bmp\|` |

`走距离` 用编码器差分做同步，让车走直线：

```python
diff = left - right
left_speed  = sp - diff * 0.3
right_speed = sp + diff * 0.3
left_speed  = max(0, min(sp * 1.2, left_speed))    # 限幅在 0 ~ 1.2 倍
```

即"哪边走得多了就压哪边"，力度系数 `0.3`。注意同步逻辑**全部用正数计算**，最后才乘上 `sign` 整体翻方向 —— 这样倒退时同步逻辑不需要另写一套。

> 💡 后退请用 **`走距离` 把速度填负数**，而不是给编码值填负数（编码值填负数也会被当成正数）。

### 4. `左/右 转到线`

原地反向转，扫到线就停。用**两段判定**避免误判：

```python
def turn_left_line():
    speed_control(-40, 40)              # 左轮退、右轮进
    while not on_line(先到通道):  pass
    while not on_line(后到通道):  pass
    speed_control(0, 0)
```

两段通道按阵列类型不同：

| 模式 | 左转 | 右转 |
| --- | --- | --- |
| 4 光电 | P1 → P3 | P4 → P2 |
| 循迹卡 | ch1 → ch4 | ch7 → ch4 |

先扫到最外侧（确认"碰到了线的边缘"），再扫到中间（"线已经在车底"）才停 —— 只判一次的话，车身还在斜着就会停。

转弯速度固定 `40`（底层常量 `var_zhuan_wan_su_du`），积木不提供参数。

## 六、算法原理

### 6.1 4 光电：差值法

```python
var_wu_cha_zhi = sensor.GetLightSensor(3) - sensor.GetLightSensor(2)
_integral += var_wu_cha_zhi          # 带 ±PID_I4_LIMIT 限幅
var_wei_fen = var_wu_cha_zhi - _cz_last_err
out = err * Kp + integral * Ki + diff * Kd
speed_control(speed - out, speed + out)
```

三个细节：

- **I 项限幅 ±20000** —— 原始光值量纲大，不加限幅积分很快就饱和，表现为"过弯后疯狂回摆"；
- **第一次运行跳过 D 项**（`_cz_first`）—— 否则 `last_err` 初始为 0，开机会被猛地拽一下；
- **白线时左右轮符号互换** —— 黑线的误差方向和白线相反，靠 `var_xun_xian_yan_se` 分支处理。

### 6.2 循迹卡：重心法

```python
w = [-3, -2, -1, 0, 1, 2, 3]
sum_v = Σ(压线 ? 100 : 0)
sum_w = Σ(v × w[i])
error = sum_w / sum_v * 33.0        # 归一化到 ±100
```

比差值法的优势是**用上了全部 7 路**，线在阵列任意位置都能给出连续偏差，而不是只看两路。

**脱线处理**：`sum_v < PID_MIN_SUM`（一路都没压线）时，沿最后一次的方向给满舵 `±100` 去找线，并且**冻结积分**防止积分爆掉；重新入线的那一拍**跳过 D 项**，否则误差从 0 突跳到几十，D 项会瞬间满舵把车拽飞。

### 6.3 循迹卡压线电平自适应

不同批次 / 固件的循迹卡，通道值约定不一样：

| 约定 | `1` 的含义 |
| --- | --- |
| A | 检测到线（卡自带阈值，不分黑白） |
| B | 看到亮/白（和 4 光电一样看相对光值） |

写死一个值，总有一种线会"巡反" —— 这就是以前"黑线能巡、白线巡不了"的根本原因。`trace_level()` 的做法：

- **白线**：两种约定下压线都是 `1`，直接取 `1`；
- **黑线**：两种约定分叉。线是窄的 → **压线的通道数一定少于不压线的** → 数一遍 7 路，少数派的那个电平就是"压线"：
  - `n1 ∈ [1,3]` → 压线 = `1`（约定 A）
  - `n1 ≥ 5` → 压线 = `0`（约定 B）
  - `n1 = 0` 或 `4`（可能在路口/横线上）→ 判不出来，本周期先用设定值，下周期再判；
- 判定结果会**缓存**，切换黑/白线地图时自动失效重判；
- 需要强制指定时改底层常量 `PID_TRACE_LEVEL`：`-1` 自动（推荐）/ `0` / `1`。

### 6.4 路口判定

```python
k = PID_JUNC_EDGE          # 最外侧连续几路压线才算，默认 1
left  = 最左连续 k 路都压线
right = 最右连续 k 路都压线

左路口 = left and not right
右路口 = right and not left
T路口  = left and right
```

`PID_JUNC_EDGE` 调到 `2` 可以过滤掉单点反光造成的误判，代价是灵敏度下降。

### 6.5 电机死区

`PID_DEADZONE` 默认 `0`（关闭）。开启后做**线性重映射**而不是简单的"小于死区就置零"：

```python
a = DEADZONE + |sp| * (100 - DEADZONE) / 100
```

把 `[0,100]` 拉伸映射到 `[DEADZONE,100]`，保住全量程，增益只略有下降。置零的写法会丢掉低速段的分辨率，过弯时容易一顿一顿的。

> 注意：4 光电路径里速度经过了 `dead_zone()`，循迹卡路径的 `speed ± out` 也会过，但 **`speed_control()` 内部还做了一次硬限幅**，两层保护。

## 七、可调常量速查

## 八、调试建议

1. **先验证传感器**：用「数据测试」拓展的 `显示舵机角度` 之外，把光值 log 出来，确认"压线时数字变化"而不是一直不变；
2. **先只调 P**：`Ki = 0`、`Kd = 0`，把 Kp 加到"能跟上弯但略有摆动"，再加 Kd 压摆；
3. **Ki 一般不用**：巡线是跟踪问题，积分项只在"系统性偏差"（例如两轮速度天生不一致）时才有价值，本拓展两个模式默认 `Ki` 都是 0；
4. **摇摆**：先降 Kp，再考虑升 Kd。灰红电机的参数就是按这个顺序调出来的；
5. **过弯出界**：多半是速度太快，降 `speed` 比加 Kp 有效；
6. **路口误判**：先升 `PID_JUNC_EDGE` 到 2，不行再看是否场地反光。

## 十、注意事项

1. `初始化` 积木**必须要有**，否则其余积木调用的 `xunxian_once` 等函数不存在；
2. 修改 `PID_KP_TAB` 时**四个下标都要给值**，少一个会 `IndexError`；
3. `转编码值` 的停止条件是"**任意一轮**超过目标"，两轮速度差很大时，走的距离会比预期的短；
4. `走距离` 的同步系数 `0.3` 是写死的，轮子打滑严重时可能需要调小；
5. `巡线距离` 的速度不支持负数（倒退请用 `走距离`）；
6. 白线巡线时，`初始化` 里的颜色必须选"白线"，否则差值法的符号是反的，车会往线的反方向跑。
