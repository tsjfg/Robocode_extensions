# 数据测试（`test`）

> Robocode 拓展 · 调试辅助类积木包 —— 把舵机角度、马达编码值实时打到屏幕上，并提供一块 8 格触屏任务面板。

| 项目 | 值 |
| --- | --- |
| 拓展 ID | `TeStQmZxNvRbLhJdWkCp` |
| 显示名称 | 数据测试 |
| 支持设备 | `E6` / `E7` / `M6` |
| 生成代码 | Python |
| 所需模块 | `servo`、`motor`、`rcu` |
| 积木颜色 | `#006eff` / `#0058cc` |

本拓展属于调试工具，不参与比赛逻辑。它的两个核心用途是：

1. **验证硬件** —— 装好舵机和马达后，先看一眼角度和编码值对不对，比盲猜接线省事得多；
2. **现场调参** —— 把几个常用动作写进任务格，上车后点屏幕就能单独跑某一项，不用反复改程序、重新下载。

---

## 一、安装

1. 把 `test/` 整个目录放进 Robocode 平台的拓展加载目录；
2. 在平台的项目里刷新 / 重新加载拓展列表；
3. 积木面板中出现 **「数据测试」** 分类，即为加载成功。

> 目录内的 `config.json` 与 `index.js` 必须保持同级，`img/` 下的 SVG 图标不能被改名。

## 二、积木清单

### 1. `释放所有舵机`

把 P1～P8 **全部 8 路**舵机置为 0 转矩（断电松手）。

用于程序结束前收纳，或发现舵机堵转发热时紧急卸力。

> 注意：本拓展释放的是 8 路，比「舵机狗」拓展的 4 路更多。

生成的底层函数：

```python
def release_servos():
    servo.SetMagneticServoMotor(1, 0)
    # ... 一直到 8
```

### 2. `显示舵机角度 [端口]`

把所选端口的舵机角度实时显示在屏幕上，下拉可选 **P1～P8** 或 **全部**。

- 屏幕 240×320，采用 **2 列 × 4 行** 布局，恰好放下 8 路；
- 亮青色（`0x07FF`）文字、黑底；
- 积木会先对所选舵机下发一次 `SetMagneticServoMotor(i, 0)`（卸力），再进入 `while True` 循环刷新角度，**因此这个积木会阻塞后续积木**，通常放在程序最后。

屏幕坐标（实测 Y 轴向上增长）：

| 端口 | (x, y) | 端口 | (x, y) |
| --- | --- | --- | --- |
| P1 | (0, 40) | P2 | (120, 40) |
| P3 | (0, 110) | P4 | (120, 110) |
| P5 | (0, 180) | P6 | (120, 180) |
| P7 | (0, 250) | P8 | (120, 250) |

### 3. `显示马达编码值`

四轮马达编码值 + M1/M2 平均值的实时监视器。

- M1、M3 在左列（x = 0）
- M2、M4 在右列（x = 180）
- 中间一行 `M1M2平均：` 用黄色（`0xFFE0`）显示，方便对照巡线的编码值目标；
- **按左键**（`rcu.GetLeftButton()`）可随时把 4 路编码值清零，不用重启程序；
- 循环内带 `rcu.SetWaitForTime(0.1)`，所以是 10Hz 刷新，同样会阻塞后续积木。

> 💡 **数值变短会残留旧数字**：`1500 → 0` 如果不补空格，屏幕上会留下 `0500`，看起来像数据错了。源码里因此在每个数字后面补了空格（左列 8 个、右列 3 个，右列紧贴屏幕边缘所以超出部分本来就被裁掉），修改布局时别忘了这个细节。

### 4. `任务面板 [方向] · 任务1 ~ 任务8`

一块 **2 列 × 4 行 = 8 格** 的触屏任务盘，每一格可以挂一段子堆栈。

| 行为 | 说明 |
| --- | --- |
| 点击某一格 | 执行该格对应的子堆栈 |
| 点击 **任务8** | 依次执行 任务1 → 任务7（"全流程跑一遍"） |
| 子堆栈为空 | 自动填 `pass`，不会报错 |
| 方向下拉 | `任务1在下方`（默认）/ `任务1在上方`，用于适配不同安装方向 |

点击判定用的是**曼哈顿距离取最近格**（`abs(dx) + abs(dy)` 最小者），而不是严格的矩形区域判断 —— 这样即使手指点偏到格子外面，也能落到最近的那个任务上，小屏幕下命中率高得多。

"任务8 = 依次执行 1～7"的设计目的是：把单步调试好的 7 个动作串成一条完整流程，一键跑完全程。

#### 面板内外的"显示"积木行为不同

这是本拓展最需要注意的一处设计。`显示舵机角度` / `显示马达编码值` 放在**面板外面**时，会各自开一个 `while True` 死循环；但**放进任务格子里**时，如果还这么干：

- 任务函数永远不返回 → 面板的触摸轮询被卡死，再也点不动；
- 两边画面还互相覆盖，谁也看不清。

所以源码用一个 `panelDepth` 计数器在**代码生成期**判断当前是否在任务堆栈里：

| 位置 | 生成的代码 |
| --- | --- |
| 面板外 | `def show_angles(): ... while True: ...` + 直接调用 → 独立死循环 |
| 面板内 | `def _p_frame_xxx(): <只画一次>` + 把该函数登记到 `_p_live` 列表 |

面板内被登记到 `_p_live` 的刷新函数，由面板主循环统一以 20Hz 调用（`SetWaitForTime(0.05)`）。

#### 一个已知的行为约束

一旦某个任务登记了刷新函数（即用了显示类积木），面板主循环会**把屏幕完全交给它**：

```python
if len(_p_live) > 0:
    while True:
        for _p_f in _p_live:
            _p_f()
        rcu.SetWaitForTime(0.05)
```

此时不再画任务格、也不再响应触摸 —— 因为屏幕被数据占满了，叠上任务格只会互相污染。**想换一个任务，请复位后重跑程序。** 这是刻意取舍，不是 bug。

## 三、生成代码示例

积木串（示意）：

```
释放所有舵机
任务面板 [任务1在下方]
    ├ 任务1: 前进...
    ├ 任务2: 显示舵机角度 [全部]
    └ 任务8: (依次执行 1~7)
显示马达编码值
```

生成的结构大致是：

```python
import servo
import motor
import rcu

def release_servos():
    ...

def show_motor_code():
    ...

def task_panel():
    _p_cells = [(0, 40), (120, 40), (0, 110), (120, 110),
                (0, 180), (120, 180), (0, 250), (120, 250)]
    _p_names = ["任务1", ..., "任务8"]
    _p_live = []

    def _p_draw_panel(): ...
    def _p_task1(): ...
    def _p_task2():
        servo.SetMagneticServoMotor(1, 0)
        # ...
        _p_live.append(_p_frame_angles_12345678)

    _p_draw_panel()
    while True:
        if rcu.GetTouchScreen():
            _p_x = rcu.GetTouchScreenX()
            _p_y = rcu.GetTouchScreenY()
            while rcu.GetTouchScreen():
                rcu.SetWaitForTime(0.05)   # 等抬手，避免重复触发
            _p_sel = 0
            _p_best = 99999
            for _p_i in range(8):
                _p_d = abs(_p_x - _p_cells[_p_i][0]) + abs(_p_y - _p_cells[_p_i][1])
                if _p_d < _p_best:
                    _p_best = _p_d
                    _p_sel = _p_i + 1
            _p_live = []
            rcu.SetLCDClear(0x0000)
            if _p_sel == 8:
                _p_task1(); ...; _p_task7()
            elif _p_sel == 1:
                _p_task1()
            # ...
            if len(_p_live) > 0:
                while True:
                    for _p_f in _p_live:
                        _p_f()
                    rcu.SetWaitForTime(0.05)
            else:
                _p_draw_panel()
        rcu.SetWaitForTime(0.05)

release_servos()
show_motor_code()
task_panel()
```

任务函数内如果用到变量，会额外插入 `ScratchBlocks.Python.Globals()` 生成的 `global` 声明，保证和普通自定义积木的变量作用域一致。

## 五、注意事项

- `显示舵机角度` / `显示马达编码值` **都是阻塞积木**（面板外是死循环），一次只用其中一个，别叠着放；
- `显示舵机角度` 在开始前会卸掉所选舵机的力，如果想让舵机保持位置，不要用它；
- 面板用 `SetLCDClear(0x0000)` 清屏，会擦掉其他拓展画在屏幕上的内容；
- 屏幕分辨率与坐标方向按 240×320、Y 轴向上实测，换设备请先验证一次。
