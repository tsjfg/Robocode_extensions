## 一、硬件与姿态约定

四条腿各占一路磁性舵机，**按"膝"命名**（源码使用 `LF / RF / LB / RB` 字段名，积木文字里写作"手/脚"）：

| 端口 | 积木里叫 | 代码里叫 | 角度映射公式 |
| --- | --- | --- | --- |
| P1 | 左手 | LF（Left Front） | `(90 + a) % 360` |
| P2 | 右手 | RF（Right Front） | `(270 - a) % 360` |
| P3 | 左脚 | LB（Left Back） | `(270 + a) % 360` |
| P4 | 右脚 | RB（Right Back） | `(90 - a) % 360` |

积木里填的 **`a` 是"相对站立位的偏角"**，不是舵机的绝对角度：`a = 0` 就是站立，正值 / 负值代表向两侧摆动。四路公式的对称性由 `90 / 270` 与 `±` 的差异保证，所以四条腿用同一个 `a` 就能朝同一方向摆。

所有动作最终都落到同一个底层函数上：

```python
def set_legs(pose):
    global var_speed, var_time
    if pose[0] is not None:
        servo.SetMagneticServoDegreeSpeed(1, (90 + pose[0]) % 360, var_speed)
    ...
    rcu.SetWaitForTime(var_time)
```

两个关键性质：

- **`None` 表示"这条腿不动"** —— 挥手时只动一条腿，靠的就是这个；
- **每调用一次就会等 `var_time` 秒**。这是步态节拍，`set_legs` 调用几次，动作就持续几个节拍。

### 全局参数

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `var_speed` | `80` | 舵机运动速度（`SetMagneticServoDegreeSpeed` 第 3 参） |
| `var_time` | `0.15` | 每个姿态之间的停留时间（秒），即节拍 |

两者由 `初始化` 积木写成模块级变量默认值，后续可用 `将速度设为 [...]，节拍设为 [...] 秒` 随时覆盖。

## 二、⚠️ 使用前必读：`初始化` 积木的两个作用

这是本拓展最容易踩坑的地方，请务必读完这一节再接硬件。

### 作用一：注入 `set_legs` 底层函数

`set_legs()` 只在 **`初始化`** 积木里通过 `functionNames_` 注册。也就是说：

> **一个程序里如果没有 `初始化` 积木，其他所有积木生成的代码都会 `NameError: set_legs`。**

因为 `functionNames_` 是**按函数名去重**的字典，其他积木只负责注册自己的 `walk_forward` / `sit_down` 之类，没人注册 `set_legs`。所以：

**每个含舵机狗积木的程序，第一个积木必须是 `初始化`。**

它生成的代码：

```python
set_legs([0, 0, 0, 0])
rcu.SetWaitForTime(0.3)
```

即"复位到站立姿态并多等 0.3 秒"，上电后先站稳再执行后续动作。

### 作用二：设置默认速度与节拍

`初始化` 通过 `definition_variables` 写入 `var_speed=80` / `var_time=0.15`。这两个默认值只在没有手动调用 `将速度设为...` 时生效。

## 三、积木清单

### 基础动作

| 积木 | 生成的函数 | 说明 |
| --- | --- | --- |
| `初始化` | — | 复位站立 + 注入 `set_legs`，**必须放在最前面** |
| `前进 [steps] 次` | `walk_forward(steps)` | 每"次"= 8 个姿态的完整循环 |
| `后退 [steps] 次` | `walk_backward(steps)` | 前进序列的镜像 |
| `左转 [steps] 次` | `turn_left(steps)` | 原地转向，每次内部循环 **6 拍** |
| `右转 [steps] 次` | `turn_right(steps)` | 同上，方向相反 |
| `站立` | `stand_upright()` | `[0,0,0,0]` 复位 |
| `坐下` | `sit_down()` | `[0,0,40,40]` 后腿抬起 |
| `趴下` | `lie_down()` | `[80,80,80,80]` 四腿全部压低 |

`前进` 的完整步态序列（这是理解所有步态的基础）：

```python
def walk_forward(steps):
    for _ in range(steps):
        set_legs([  0, 40, 40,  0])
        set_legs([-40, 40, 40,-40])
        set_legs([-40,  0,  0,-40])
        set_legs([  0,  0,  0,  0])
        set_legs([ 40,  0,  0, 40])
        set_legs([ 40,-40,-40, 40])
        set_legs([  0,-40,-40,  0])
        set_legs([  0,  0,  0,  0])
    rcu.SetWaitForTime(0.2)
```

8 拍构成一个完整的"迈步—支撑—抬腿—回正"周期，`后退` 就是这 8 拍**倒序**执行，所以后退不需要单独调参，前进走顺了后退自然就对。

> ⏱ **耗时估算**：`前进 1 次` ≈ 8 × 0.15s = 1.2s。`左转 1 次` ≈ 6 × 4 × 0.15s = 3.6s —— **转向明显比前进慢**，编队形时要按这个比例配步数。

### 叫声与表演

| 积木 | 说明 |
| --- | --- |
| `狗叫 [叫声类型]` | `叫声1` → `xm4077.mp3`，`叫声2` → `xm4081.mp3`，用 `rcu.SetAudioPlay()` 播放 |

`执行动作 [动作]` 下拉五种：

| 选项 | 函数 | 动作描述 |
| --- | --- | --- |
| 前顶 | `push_front()` | 前腿下压再复位，像用头拱一下 |
| 后顶 | `push_rear()` | 后腿下压再复位 |
| 左挥手 | `wave_left()` | 三腿站定，左手在 `100 ↔ 60` 度间抬落 **6 次** |
| 右挥手 | `wave_right()` | 右手挥手，同理 |
| 摇摆 | `sway()` | 四腿同时 `+30 / -30` 往复 **5 次**，身体左右晃 |

挥手动作演示了 `None` 的用法 —— 只写第 1 路，其余三路保持原状：

```python
def wave_left():
    set_legs([0, 0, 0, 0])
    set_legs([45, 45, 45, -45])       # 先摆出"三腿支撑"的预备姿势
    for count in range(6):
        set_legs([100, None, None, None])
        rcu.SetWaitForTime(0.1)
        set_legs([60, None, None, None])
    rcu.SetWaitForTime(0.5)
    set_legs([0, 0, 0, 0])
```

### 精细控制

| 积木 | 说明 |
| --- | --- |
| `[腿] 抬起 [angle] 度` | 单独摆一条腿。下拉可选 左手 / 右手 / 左脚 / 右脚 / 全部 |
| `将姿势设为左手 [LF] 右手 [RF] 左脚 [LB] 右脚 [RB]` | 直接给四腿角度，一行摆出任意姿态 |

单腿抬起会**临时把节拍设为 0**，让动作瞬间到位（手动摆姿势时不需要等节拍）：

```python
def set_leg_angle(leg_num, angle):
    global var_time
    temp_time = var_time
    var_time = 0
    ...
    var_time = temp_time      # 结束后恢复
```

> 注意 `全部` 在菜单里的 value 是 `"1234"`，对应源码中 `elif leg_num == 1234:` 分支，**四腿同时摆同一个角度**；而 `将姿势设为...` 则是四腿各给各的值。

### 状态与参数

| 积木 | 说明 |
| --- | --- |
| `释放所有舵机` | P1～P4 全部置 0 转矩。**注意只释放前 4 路**（与「数据测试」拓展的 8 路不同） |
| `显示当前角度` | 把 P1～P4 角度打到屏幕四角。**只画一次，不是死循环**，需要持续刷新请自行放进循环 |
| `将速度设为 [speed]，节拍设为 [time] 秒` | 覆盖全局 `var_speed` / `var_time` |

`显示当前角度` 的坐标：P1 (0,40)、P2 (180,40)、P3 (0,240)、P4 (180,240)。

## 四、典型用法

### 1. 最小可用程序

```
初始化
前进 3 次
左转 1 次
狗叫 [叫声1]
坐下
```

### 2. 调参流程建议

1. 先只放 `初始化` + `显示当前角度`，确认四条腿都停在中位；
2. 用 `[腿] 抬起 45 度` 逐条腿验证方向 —— 如果某条腿反向，检查 P1～P4 的接线顺序；
3. 速度先设 `60`、节拍设 `0.2` 跑 `前进 1 次`，走稳了再往上加速度、往下压节拍；
4. 步态参数（`40` / `-40` 这些角度）如需改动，直接在生成的 Python 里调，确认效果后再回写到拓展。

### 3. 与「数据测试」拓展配合

现场调试机器狗时，可以先用「数据测试」的 `任务面板` 把 `站立 / 坐下 / 挥手` 各挂一格，点屏幕单独验证动作，再串进正式程序。

## 六、注意事项（踩坑清单）

1. **没有 `初始化` 就必然报 `NameError`** —— 见第二节，这是最高频的问题；
2. **`初始化` 只应出现在程序开头一次**，它不是幂等的状态查询，而是一次实际动作；
3. `释放所有舵机` 只释放 P1～P4，别的端口的舵机需要另外处理；
4. `坐下` 与 `趴下` 之后不会自动回正，需要显式 `站立`；
5. 转向比前进慢 3 倍（6 拍 × 4 步 vs 8 拍），配时间时容易算错；
6. `config.json` 里的 `description` 仍是占位文字 `"扩展描述"`，如需在平台显示描述请自行补全；
7. 平台侧若改变了 `functionNames_` 的注入顺序（例如不再保证"按使用顺序追加"），`set_legs` 依赖 `初始化` 的设计就需要重新审视。
